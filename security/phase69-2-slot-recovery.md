# Slot recovery preview
Reuses waiting list and cancellation matching. One pending offer per supplied slot state, oldest eligible unoffered customer, 5–120 minute deadline capped by request expiry and slot start. Expiry and decline allow next customer, acceptance terminal. Rechecks availability and request identity on response; returns immutable state only. No actual slot lock, notification, booking or persistence. Production requires verified customer authentication, trusted clock, authoritative service and schedule, atomic cross-slot hold/booking/waitlist transaction, global overlap protection across distinct cancellation IDs, secure response tokens, durable idempotency, scheduler and consent. Same-snapshot concurrent calls can both propose; acceptance is not a booking. No deployment.
