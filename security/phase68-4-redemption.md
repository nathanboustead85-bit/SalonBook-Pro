# Reward redemption preview
Owner-only pure calculation; free service tied to supplied service ID, integer percentage rounded down, fixed discount capped at price. Reward validity is half-open [start, expiry). Explicit confirmation, matching candidate/current reward and account, positive cost, sufficient balance, revision increment and per-account redemption ID replay checks. Returns a new account without persistence. Caller-supplied snapshots and prices are not authoritative; no atomic ledger, booking binding, durable idempotency, programme/unit binding, refund reversal, customer authorization, stacking rules, tax/payment reconciliation or real redemption. Concurrent calls on same snapshot can both return proposals; production must atomically compare revision and commit ledger plus booking. No live deployment.
