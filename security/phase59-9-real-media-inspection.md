# Phase 59.9 — Actual media decoding and audio duration inspection

Implemented `chat/media-processing.cjs` with Sharp image pixel decoding and metadata-stripping JPEG re-encoding, plus ffprobe duration extraction from actual audio bytes stored temporarily in a restricted temporary directory. Both are integrated with the existing media-validation foundation and tested against generated real PNG and WebM files, a corrupt PNG header, corrupt audio and a >60-second recording.

**Limits and remaining launch blockers:** The processing runs as a Node library in GitHub Actions, not a deployed media service. ffprobe is an external executable and must be sandboxed with CPU/memory limits, container isolation and secure binary provenance before accepting untrusted files. No malware scanning, audio transcoding, content moderation, Storage rules, authenticated upload flow, quota reservation, metadata and object ownership verification, deletion policy or media endpoint exists. The returned processed bytes are not uploaded; callers must store only the sanitized image bytes, never the originals. The image re-encoder strips EXIF but further privacy review is required. G1–G7 stay OPEN. Live messaging, payments and deployment disabled. No Android appointments accessed.
