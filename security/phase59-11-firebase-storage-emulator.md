# Phase 59.11 — Firebase Storage emulator integration (offline only)

Implemented `chat/firebase-storage-emulator.cjs` using the Firebase Admin SDK Storage bucket against a **real Firebase Storage emulator**, gated by `FIREBASE_STORAGE_EMULATOR_HOST` and disabled by default. The test flow authenticates a synthetic participant against a trusted in-memory conversation loader, decodes and sanitizes an image, writes the sanitized JPEG into emulator object storage, checks object metadata, downloads it as another participant, verifies the SHA-256 digest, and denies an outsider and path traversal. Storage rules for this test harness deny all client reads and writes; Admin SDK bypasses rules, so server-side membership checks are essential.

**Important security limitations:** This is an emulator-only adapter, not a deployed service. `auth` is an injected synthetic trusted identity; a production endpoint must verify Firebase ID tokens, derive identity and business membership server-side, use Firestore transaction-backed conversation records, App Check and quotas, and verify all object ownership. A production Storage Rules policy, media malware scanning, hardened audio sandbox, upload lifecycle, object retention/deletion and independent review remain outstanding. No real customer media was uploaded and no production Firebase credentials or services were used. G1–G7 OPEN; messaging, bookings, payments and deployment remain disabled. No Android data or appointments accessed.
