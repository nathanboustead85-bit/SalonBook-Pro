# Phase 12.43 — Availability withdrawal and expiry

**Emulator-only prototype; no production deployment.** Trusted Admin test worker reads the private source documents and existing public snapshot inside a Firestore transaction. It atomically replaces the snapshot when the source is valid, or deletes it when unpublished, missing, invalid, or mismatched. A separate private publication watermark prevents older workers from republishing a deleted snapshot. Public snapshot expires after 5 minutes; emulator Firestore rules deny expired reads based on server request time, not only the browser clock. All client writes, public collection listing and private source reads remain denied.

Limitations: this is a **reconciliation function, not a deployed trigger or scheduled job**. Unpublishing takes effect only when reconciliation is invoked; otherwise the existing snapshot can remain readable until its 5-minute expiry. The public document is not physically deleted by TTL alone. Source reads are still emulator fixture schema, not real Android liveData. Date/timezone/DST, real data mapping, scheduling, operational monitoring, release approvals and production-rule review remain outstanding. Booking creation remains disabled; production readiness is NOT READY. No original Android appointments or live Firebase data are touched.
