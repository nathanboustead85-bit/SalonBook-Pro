# Phase 36.3 — Isolated Firebase Auth listener lifecycle

Dependency-injected `createAuthListenerController` wires the Firebase `onIdTokenChanged` listener to Phase 36.2 verified-owner sessions and the Phase 36.1 read-only Android-schema Firestore adapter. It automatically validates a fresh ID token on login and token changes, and fails closed on sign-out, owner switch, expired/unverified tokens, listener errors and network outage. Network restoration explicitly revalidates the current user. `stop()` unsubscribes and clears private data. Generation guards prevent stale asynchronous refresh results from publishing.

Tests run real Firebase Auth and Firestore emulators under demo project `demo-boustio-phase36-3`, with synthetic verified users created using emulator-only Admin SDK. Firestore security contexts are provided by rules-unit-testing; this **does not yet test an Auth token directly attached to a Firestore client**. Network failures and pending refreshes are simulated, not real device connectivity tests. Listener callbacks must be started and stopped by a future application integration. No production Firebase initialized, no live booking/payment/messaging or deployment, no production rules/config changes, and no Android appointments accessed.
